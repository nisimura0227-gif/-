# 現場のお弁当注文サイト

建設現場向けのスマホ用お弁当注文サイトです。Next.js（App Router）+ TypeScript + Tailwind CSS で作成しています。

## セットアップ

```bash
npm install
cp .env.example .env   # 管理者パスワードなどを設定
npm run dev
```

`http://localhost:3000` を開くと動作確認できます。

### 環境変数（.env）

| 変数名 | 内容 |
|---|---|
| `ADMIN_PASSWORD` | 管理者ログインのパスワード（初期値 `admin123`。必ず変更してください） |
| `SESSION_SECRET` | 管理者ログインセッションの署名用シークレット（ランダムな文字列に変更してください） |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | Vercelなど永続ディスクが無い環境で使う場合に設定（無料枠あり） |
| `DATA_DIR` | データ保存先フォルダ（省略可）。永続ディスクが使える環境（Railwayなど）でRedisを使わない場合のみ設定 |
| `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_CHANNEL_SECRET` | 公式LINE連携（任意）。Messaging APIのトークン・シークレット |
| `NEXT_PUBLIC_LIFF_ID` | 公式LINE連携（任意）。LINEアカウントとサイトの「名前」を紐付けるためのLIFFアプリID |
| `NEXT_PUBLIC_SITE_URL` | 公式LINE連携（任意）。通知メッセージ内のリンク生成に使用 |
| `CRON_SECRET` | 公式LINE連携（任意）。定時通知Cronの認証用ランダム文字列 |

LINE関連の変数はすべて未設定でも、サイトの注文・管理機能は問題なく動きます。設定手順は `LINE設定用/公式LINE_MessagingAPI・LIFF設定手順.md` を参照してください。

## 主な機能

- トップページ：今週のメニュー画像（タップで拡大）／今日・明日の注文ボタン
- 今日の注文：名前・メニューを選んで注文（支払いは「手渡し」固定）。**7:55（日本時間）を過ぎると自動的に受付終了**になります
- 明日の注文：名前・メニューを選んで注文（支払いは前日中の手渡し）。**本日15:00（日本時間）を過ぎると自動的に受付終了**になります。当日朝の集金は行いません
- 現金は必ず担当者へ直接手渡しします。ケースへの投函（保管）は事故防止のため廃止しました
- 支払い状況は「支払い待ち → 本人が「渡しました」と申告 → 管理者が受け取りを確認（支払い済み）」の3段階。本人の申告だけでは支払い済みになりません
- 公式LINE連携（設定した場合）
  - 新しい注文・支払い申告のたびに管理者へLINE通知（オン/オフ切替可）
  - 管理者はLINEの「受け取り確認」ボタンをタップするだけで支払い確定
  - 利用者へは注文完了・支払い確認をLINEで自動通知、毎朝6:30に受付リマインドを送信
  - 前日15:00（明日の注文締切）に、注文状況のサマリーを管理者へ自動通知
- 管理画面（`/admin/login` からログイン）
  - 今日・明日の注文一覧とメニュー別自動集計、支払い状況の確認・変更
  - 過去の注文履歴（日付ごと）
  - メニュー管理（追加・編集・削除）
  - 名前管理（追加・編集・削除）
  - 今週のメニュー画像の差し替え
  - 締切時刻・LINE通知先などの設定変更

## データの保存について（重要）

データ保存先は環境変数によって自動的に切り替わります（`lib/store.ts` が判定）。

- **`UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` が設定されている場合**
  → Upstash Redis（無料枠あり）にデータ・画像を保存します。Vercelのようなサーバーレス環境で永続化したい場合はこちらを使います。
- **どちらも未設定の場合**
  → `DATA_DIR`（省略時は `data/db/`）以下のJSONファイル・画像ファイルに保存します。ローカル動作確認や、永続ディスクが使えるホスティング先（Railwayなど）向けです。

データは自動では削除されません。容量が小さいため保存し続けても問題にならず、「注文したはずなのに」といった食い違いがあった際の記録としても使えます。

## デプロイ

初めての方は同梱のガイドを参照してください。

- **無料で公開したい場合**：`公開手順ガイド_Vercel無料版.md`（Vercel + Upstash Redis）
- **月額数百円〜のホスティングで、より単純な構成にしたい場合**：`公開手順ガイド.md`（Railway、ボリューム方式）

Next.js標準の構成なので、どちらの方法でも `next build` / `next start` でそのままデプロイできます。

## 初期データについて

`data/seed/` にサンプルの名前・メニューが入っています。初回起動時に自動的に `data/db/` へコピーされます。実際の名前・メニューは管理画面（名前管理／メニュー管理）から登録・編集してください。

## 動作確認について

このプロジェクトはネットワーク制限のある環境で作成したため、`npm install` を伴う実際のビルド確認ができていません。コードの構文チェック（括弧の対応・JSON妥当性など）は実施済みですが、お手元で `npm install && npm run build` を実行して最終確認をお願いします。
